# AI 私厨管家实施计划

日期：2026-11-11

## 交付目标

在 `D:\cookagent` 交付一个本地可运行的前后端项目：FastAPI + LangChain Python 后端，React/Vite 前端，使用阿里云百炼 `qwen3.7-plus` 完成食材图片识别、菜谱生成与上下文问答，并通过 Tavily 提供可追溯的网络资料。

## 实施步骤

1. **配置与项目骨架**
   - 创建根目录 `.gitignore`、`.env.example`、README。
   - 真实模型与 Tavily 凭据仅写入本地 `.env`。
   - 后端通过 `load_dotenv()` 加载根目录配置。

2. **FastAPI/LangChain 后端**
   - 定义 Pydantic 领域模型、统一错误格式和内存会话仓库。
   - 实现图片格式/大小校验及 Base64 多模态请求。
   - 用 `ChatOpenAI` 接入工作空间专属 OpenAI 兼容地址和 `qwen3.7-plus`。
   - 用结构化输出实现食材识别与菜谱生成。
   - 用 LangChain Tavily Tool 搜索候选资料，并保留标题与 URL。
   - 实现确定性排序、过敏原绝对过滤及上下文聊天。
   - 暴露健康检查、识别、推荐、聊天和会话 API。

3. **React/Vite 前端**
   - 实现图片拖拽上传、预览、识别状态与错误恢复。
   - 实现食材增删改、偏好表单和过敏原独立输入。
   - 实现菜谱卡片、评分解释、筛选排序、来源展示和步骤详情。
   - 实现当前会话聊天区和响应式移动布局。
   - 采用米白、番茄红与香草绿的现代厨房视觉。

4. **测试与静态验证**
   - 后端覆盖配置、图片校验、排序、API 主流程与降级路径。
   - 前端覆盖关键渲染与构建/类型检查。
   - 检查 `.env` 未被 Git 跟踪、前端产物不含密钥。

5. **真实连通与预览**
   - 使用实际环境变量检查模型与 Tavily 服务连通性，输出只保留成功状态和耗时。
   - 启动后端和前端，验证健康端点与首页 HTTP 状态。
   - 如本机预览工具可用，检查桌面和移动端关键布局。

## 完成标准

- 前后端依赖可安装，测试与构建通过。
- 真实模型接口和 Tavily 至少完成一次脱敏连通性检查。
- 用户可从上传图片走完“识别—确认—推荐—查看—追问”流程。
- 真实密钥只存在于被忽略的 `.env`，不进入源码、日志或前端产物。
